## Riesgo adicional confirmado: alta antigua dentro del MVP

`routes/scheduling.php` mantiene POST `/scheduling-mvp/agenda/appointments` protegido por CREATE. `AgendaAppointmentController::store` llama a `CreateAppointmentService::create`, que crea estado_agenda LEGADO, total_pagado=0, sin exigir adelanto. `AppointmentAgendaLifecycle::occupiesInterval` hace que LEGADO/PROGRAMADO ocupe intervalo. El formulario operativo nuevo usa `/registrations` y sí exige 50% para CONFIRM regular, pero un actor con CREATE todavía puede invocar el endpoint antiguo para ocupar cupo sin esa regla. Este riesgo de bypass es del código base; no explica el disabled productivo actual y no se explotó ni se crearon citas reales.

Por ello, antes de recomendar la activación de CREATE para una operadora, cerrar o adaptar esa alta antigua del MVP: unificarla con reserva pendiente o registro operativo validado, manteniendo registros históricos y reglas de ocupación. Añadir prueba de petición directa al endpoint antiguo para que no pueda confirmar/ocupar una cita regular nueva impaga. No modificar ni borrar citas LEGADO existentes y no conceder capabilities de adicionales/exoneración como solución. La revisión de escrituras heredadas fuera del MVP debe cubrirse en la implementación autorizada para comprobar consistencia antes de declarar que no existen bypasses.

## OCR: decisión técnica pendiente de evidencia del hosting

No se escoge motor ni se habilita proveedor externo. En este equipo PHP CLI=8.0.30 con fileinfo/PDO SQLite, sin Tesseract en PATH; esto NO representa Hostinger. [Tesseract](https://github.com/tesseract-ocr/tessdoc/blob/main/InputFormats.md) requiere convertir PDF a imágenes: no acepta PDF directamente.

Antes de elegir: inventario sanitizado del PHP CLI y web, proc_open/exec permitidos, binarios y versiones Tesseract/Poppler, idiomas spa/eng, upload_max_filesize/post_max_size/max_file_uploads, memoria/CPU/disco, límite de páginas y resolución, y soporte de cron/cola. Medir solo con comprobantes ficticios. No modificar hPanel/SSH ni habilitar funciones en este trabajo. Candidato si viable: procesamiento local aislado con timeout, máximo de páginas/píxeles, rutas internas y argumentos sin shell, PDF con texto primero y rasterizado acotado para escaneos. Alternativa: OCR en equipo controlado o captura manual. Servicio externo solo después de aprobación explícita de destinatario, tratamiento/retención y costo; ningún fallback externo automático.

Contrato futuro: documento privado -> estado PENDIENTE/PROCESANDO/REVISAR/ERROR -> sugerencias {monto, operación, entidad/medio, fecha/hora, confianza por campo, motor/versión} -> edición y confirmación manual con actor/fecha/revisión -> solicitud explícita de registrar pago con SUBMIT_PAYMENT y controles actuales. Fecha bancaria no reemplaza created_at. Mantener documento original, hash, vínculo a operación y pago, extracción original y correcciones en historial privado. No volcar texto OCR en logs/telemetría. Lectura fallida deja todos los campos editables. Reintento OCR idempotente documento/hash/motor/versión; evidencia idéntica y operación bancaria duplicada se revisan antes de cualquier dinero.
